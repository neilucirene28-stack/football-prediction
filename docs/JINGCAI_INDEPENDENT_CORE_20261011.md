# 竞彩 v12：独立计算流程与配置

## 已完成

竞彩生产入口 engine.jingcai_predictor 不再调用 engine.predictor，改用独立的 jingcai_core。移除双模式分支和北单输出，计算核心也执行竞彩范围校验；调用方不能通过绕过外层入口来传入其他项目输入或配置。

默认参数和弱赛事集合由 jingcai_config 独立持有；让平分档、联赛先验及矩阵修正由 jingcai_letdraw 独立持有。本轮沿用 v11 参数数值和算术，不声称重新训练或提升命中率。旧 letdraw 参数对象的变更不会传播到竞彩新核心。

engine 包初始化不再主动导入旧双模式核心或北单模块。旧版包级导出保留为延迟加载以兼容已有调用；显式请求旧导出时才加载对应模块。API及竞彩脚本继续使用 engine.jingcai_predictor。旧 engine.predict 和 engine.predictor.predict 是兼容入口，竞彩新增生产代码不要使用它们。

公共 PredictError 移至不含任何模型逻辑的 errors 模块，旧入口与新入口保持同一异常类型。通用 Poisson、Elo、攻防估计、市场融合等数学工具仍复用；这次完成的是竞彩业务流程与参数管理独立，并未复制全部依赖或建立独立部署服务器。后续通用数学模块变更仍需要两边分别验证。

## 校准文件

默认 Platt 读取路径改为 engine/jingcai_calibration.json。新文件明确禁用，等待真实赛前样本和按时间划分的验证。旧 calibration.json 不再被竞彩自动读取，不自动搬迁没有版本和截止证据的参数。只有另行核验过的竞彩参数包才能通过显式路径进入候选加载，计算时仍验证基础版本、信号范围及训练/验证/拟合时间。

版本修订为 jingcai-independent-core-20261011-v12，模型和基础版本哈希随之变化。v11校准包不能直接跨版本套用；历史封存记录保持原版本，不改写或补写赛前情报。

## 测试与验证

新增25项核心隔离/兼容/算术检查，迁移竞彩专项测试到生产专用入口。关键检查包括：在临时项目删除旧 predictor.py、letdraw.py、calibration.json 和所有北单专用文件，同时阻止相关导入后，竞彩仍可运行；修改旧核心函数或旧先验不会影响竞彩；15组让球数和强度组合与原竞彩算术一致；直接调用新核心也会拒绝其他项目范围。

核心657通过、1项缺psycopg跳过、1项北单分支排除；竞彩专项403通过；采集器70通过。原30场输入同配置只读离线回放对比v11：输入摘要、胜平负概率、比分矩阵、进球强度、置信评分、推荐及衍生概率均相同，版本哈希变化符合预期。

这些检查证明结构拆分没有改变已核对样本的计算结果，不证明未来准确率提高。合成测试不作训练数据；回放不创建新的赛前预测。

## 尚未完成

让平专项参数、球队/外援情报概率系数、红黄牌增量影响和置信度统计校准仍需真实赛前样本与独立时序验证。情报系数没有启用，商业数据密钥没有提供，代码尚未部署到MUSE。现有让平经验先验仍沿用原回填数值，其历史来源不足以替代真实赛前独立验证。
