# 竞彩 v7：让球赔率输入修复与净胜球离线验证

## 本轮结果

采集输入为 `handicap_sp={home,draw,away}`，v6校验器仅接受列表，导致10月10日30场赔率全部被排除。修复兼容对象与三项列表，固定顺序为home/draw/away，不改变调用方原输入；可选坏信号排除但在审计和用户说明中显式记录。对象只接受三项赔率及source/available_at/collected_at/feature_as_of已知元数据，赔率须有限且大于1。

元数据中的未来时间会拒绝整个预测，不被可选信号容错吞掉。available_at或feature_timestamps.handicap_sp可提供声明可得时间；缺时间保留兼容诊断，并注明未核验赛前可得，不能把声明时间当来源鉴真。不补造历史可得时间。

新增handicap_market_diagnostic显示去水概率、方法、盘口、分歧与预警使用状态。赔率仍不直接融合比分矩阵；已有普通胜平负市场时仅作让球诊断，缺普通胜平负市场时恢复原有让球分歧预警。预警可能下调信心，不能称为概率准确率改善。

版本增加jingcai-handicap-input-margin-validation-20261011-v7。旧预测不覆盖，新结果按新版本存储；不存在旧校准被自动带入新版本的授权。

## 结算

engine.jingcai_handicap.handicap_outcome统一按主队视角计算sign(主队进球−客队进球+官方整数让球)。scoreboard调用它。001的0–0让−1为让负；2–1让−1为让平；0–1让+1为让平；3–0让−3为让平。未知、布尔、小数比分不被转成0。

v6的scoreboard原公式本来正确；本轮将它抽成统一函数并增加实际错误场景回归，并不声称已经修改MUSE的报告生成器或服务器结算记录。

## 净胜球候选：仅离线

新增engine/jingcai_margin_validation.py及scripts/validate_jingcai_margin.py。输入与v6的只读竞彩账本导出相同，须有原输入、真实赛前生成时间、输入摘要、版本、物理比赛ID、结算来源与可得时间、完整精度比分矩阵。验证原输入摘要、赛前时间和矩阵与全场/让球概率的一致性。版本隔离，同场同版本选最早预测；冲突排除、重复结算可得时间取最晚。

固定候选log倍率为0、−0.5、+0.5、−1、+1。针对目标净胜球−rq调整矩阵中的相对概率，再在对应胜/平/负区间归一化，保持全场WDL三项边际。rq=0不改。盘口各自至少100个训练样本；未达到门槛的盘口不计候选测试表现，避免大量未修改样本稀释损失。

按UTC比赛日分批滚动，每批以最早快照作为训练截止；只有更早开赛且结算实际可得时间严格早于截止的比赛可训练。系数按训练集让球Brier选择，0系数在并列时优先，不用测试结果选参。训练早于首个测试日期也仍须符合可得时刻。

比较让球三分类Brier/LogLoss、让平二元Brier、比分LogLoss、平均进球偏差、分盘口期望与实际让平数。矩阵外实际比分显式计数，其比分概率按固定1e−12评分截断，不补造尾部概率。候选不保证保持进球均值，因此增加总体绝对均值偏差不恶化检查；至少100个有训练支持的测试场、3个时间批次，任何批次让球Brier恶化即阻断。候选未发生非零调整不视为验证了新方法。

research_screen_passed仅为固定规则研究筛查，不是统计显著性或生产准入；未校正依赖、多次研究选择与不确定性。即使筛查通过仍须独立锁定测试、真实来源核验，以及所有衍生玩法/半全场/MC的统一矩阵整合。生产永远标记false，此模块未被预测器导入，不导出可自动加载的生产参数。

```bash
python3 scripts/validate_jingcai_margin.py \
  --input /path/to/jingcai-version-ledger.jsonl \
  --output /path/to/margin-validation.json \
  --test-start 2026-10-11T00:00:00+08:00
```

测试起点必须事先固定；若已经看过该段赛果，输出只能作为探索，不能称独立锁定验证。勿降低门槛仅为让本轮29场通过。
