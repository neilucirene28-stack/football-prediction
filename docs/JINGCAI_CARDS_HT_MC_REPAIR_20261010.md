# 竞彩第五轮：赛季红黄牌、半场一致性与最终矩阵模拟

本轮只推进竞彩项目，累计保留前版修复。北单专用文件不修改。新增竞彩牌数模块，不改共享旧牌数模块的预测函数或队名匹配行为；竞彩入口已使用新模块。未部署服务器、未访问真实数据库，也没有补造2026/27赛季统计。

## 牌数模块的具体修复

旧代码存在：牌数库混合2021/22～2024/25赛季；近期记录没有预测截止过滤；模糊匹配可能把Newcastle United匹配到Man United；牌数只作衍生输出，没有赛果调整模型。

新`engine/jingcai_cards.py`：

- 接受明确联赛、赛季、起止范围、实际可得时间、来源和CSV原件SHA256的赛季统计包。赛季必须覆盖本场，统计可得时间不得晚于预测快照。
- 校验联赛均值、全体球队牌数之和及已观测场数一致；场次与牌数必须为非负有限整数。联赛/杯赛不能凭队名混用统计。
- 球队只按精确来源名称或原包已有的精确别名绑定，不做子串、United等公共词匹配。已有别名仍只是声明映射，输出不声称独立鉴真。
- 当前赛季输出双方已观测黄牌、红牌、已收集完赛场次、其中牌数完整场次、场均值及覆盖率。缺牌数不补零；覆盖率仅描述导入记录，不能证明官方全赛季完整。
- 当前赛季数据缺失时，旧统计明确标为`historical_prior_only`，当前赛季数量为`null`、置信度为低；不能把旧数量包装成本赛季数量。历史截止早于聚合库完整覆盖时，不能使用该聚合先验。
- 近期记录需精确球队/联赛/赛季、比赛ID、完赛与可得时间；取最近5个独立比赛。同场重复不累计；同场冲突整组排除；未来、无时间证据或错队记录留排除原因。
- 裁判统计区分当前赛季或历史先验。保留原收缩、近期和裁判启发式参数，没有声称新拟合或牌数准确率提高。
- 历史牌数库、别名文件的字节摘要和实际牌数参数进入模型版本哈希；每次预测使用与该摘要对应的同一份内存数据，避免缓存与文件版本不一致。

输出包括黄牌期望、总黄牌≥4/≥5概率、主队/客队/全场至少一张红牌概率及完整精度字段。booking points保留为内部近似，不用于证明任何具体牌数盘口结算。CSV的HR/AR未区分直接红牌和两黄变红，输出明确标记该信息未知，不凭空拆分。

## 当前赛季数据接入

`scripts/import_jingcai_cards_season.py`接收已获得、来源可核查的CSV，不负责联网或绕过数据权限。必需列为`Date, HomeTeam, AwayTeam, FTHG, FTAG, HY, AY, HR, AR`；有Div列时须匹配指定联赛，Referee可选。

```bash
python3 scripts/import_jingcai_cards_season.py \
  --input /path/to/verified-season.csv \
  --output data/jingcai-cards-season.json \
  --league-code E0 --league-name 英超 \
  --season 2026/27 --season-start 2026-07-01 --season-end 2027-06-30 \
  --source '实际核验的来源标识或URL' --source-timezone Europe/London
```

起止日期和时区须按实际数据源核实，命令中的赛季边界只是显式参数示例。采集可得时刻使用实际运行时间，CLI不提供倒填历史采集时间选项。只接受已结束的来源日期；日期不足以证明当天已经完赛，因此同日/未来记录排除。缺全场比分、缺牌数、错联赛及重复均有计数；同场冲突拒绝导入。空白红牌与数字0有不同含义。

预测输入中附加：

```python
import json
from engine.jingcai_predictor import predict

payload["cards"] = {
    "league_code": "E0",
    "season": "2026/27",
    "season_stats": json.load(open("data/jingcai-cards-season.json")),
    # "referee": 已确认的来源裁判名,
    # "recent_records": 有完赛/可得时间的精确球队逐场记录,
    # "confirmed_suspensions": 本场已经确认且有来源与可得时间的球员停赛记录,
}
# snapshot_at须在上述数据实际可得之后、并且在开球前。
result = predict(payload)
```

统计包保留完整球队集合，供联赛/球队总量一致性核对；不能随意删成两队而保留全联赛场数。批量列表的单场`cards`字段会传入预测器、绑定原输入并封存；与采集快照的牌数内容冲突时拒绝。批量结果与网页都展示牌数概率和可得赛季数量。

本次项目里没有真实当前赛季CSV，未抓取全在售比赛的当前赛季牌数；单元测试里的2030赛季和数量都是合成接口用例。正式运行时仍需要接入可核验的数据源，不得拿这些测试数据代替真实统计。

## 停赛与赛果影响

`confirmed_suspensions`只接受`status=confirmed`、精确来源球队、球员ID/姓名、对应赛事和本场开球时间、来源与不晚于快照的可得时间。可能停赛、其他杯赛、未来消息或其他比赛会排除。不能从球队累计黄牌推断某球员已经停赛，也不硬编码通用于所有赛事的黄牌停赛门槛。

新模块给出“无红牌/仅主队红牌/仅客队红牌/双方红牌”的风险权重，基于独立球队红牌Poisson计数假设；没有模拟红牌发生分钟或罚下球员位置。它是描述性风险，不能当作完整赛果情景模型。

**红黄牌与停赛数据尚未自动调整竞彩胜平负或λ。** `match_result_integration.status=not_applied`对此明确留痕。要启用，需要带分钟的红黄牌事件、比分状态、球队和球员暴露时间、实际停赛/首发信息，再按竞彩模型版本做时序训练和独立验证。历史进失球本就包含一些红牌影响，不能在无条件λ上再盲目减百分比造成重复计入。本轮未复制论文效果数值作为生产系数。

## 半场与半全场一致性

此前半场胜平负独立从原λ算出，而半全场联合分布已按最终全场矩阵重加权，两者的半场边际可能不同。现在竞彩半场胜平负直接聚合已有半全场九类分布的半场边际。全场胜平负、全场矩阵和半全场九类概率不因本修复改变。

`half_time_full`记录完整精度；原独立半场模型保留为`half_time_raw`。原半场比分列表明确放在`raw_model_top_scores`，不伪称已按联合分布重新校准的半场比分。既有半场展示概率会改变，不能宣称所有衍生输出不变。

## 蒙特卡洛

旧竞彩MC抽样两个独立原始Poisson，未包含DC、市场融合、IPF与让平矩阵重分配。新`engine/jingcai_montecarlo.py`直接抽样最终比分矩阵，来源标记为`jingcai_final_score_matrix`。

默认`mc_seed=0`，允许显式整数，进入版本哈希。记录完整抽样概率、目标解析胜平负、抽样标准误和偏差；数据完整度门控仍保留。模拟验证的是模型内部抽样一致性，不是独立预测准确率或完整参数不确定性区间。

## 牌数结算与复盘

原`sql/002_learning.sql`已经预留`yellow_home/yellow_away/red_home/red_away`，本轮不加迁移。新`api.api.jingcai_settlement.save_jingcai_settlement`只接受已开球的竞彩预测，记录来源，验证比分与可得牌数；未知牌数保持NULL，既有结算不覆盖。插入未成功且无合规已有记录时报错并回滚。

`scripts/settle.py`改成竞彩专用查询与写入，并修复固定机器路径。其现有详情页解析仍只取得比分，不能从无可靠牌数解析的HTML推测牌数；默认自动结算的牌数会保持NULL。若已核验实际牌数，在首次结算时通过新函数的牌数关键字参数一并写入；已有缺牌数结算不能被本函数悄悄覆盖。

复盘读取已有牌数列，新增主队/客队/全场红牌Brier和LogLoss、总黄牌≥4/≥5的Brier和LogLoss、总黄牌期望误差及偏差。缺一方牌数不计算全场对应指标；每项都有独立样本分母。没有真实牌数时输出缺失原因，不能默认没有红牌。
