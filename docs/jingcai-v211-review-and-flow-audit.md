## 按时间划分的校准回测

输入为仓库 Phase2 九月清单与战绩，共 226 个唯一目标；224 场可评估，1 场数据不足、1 场无最终赛果。过滤 3 条没有合格日期/晚于数据截止日的战绩记录；近期战绩按日期倒序，以主客队视角转换。联赛均值仅由合格的赛前战绩计算。实际回放时间与历史虚拟截止时间分别记录。

历史赔率没有可独立核验的赛前采集时间，历史赛果也缺少逐场原始响应留证，所以以下数值只代表历史研究回放，不代表真实前瞻收益或正式验收。

日期整体分组，最早 119 场训练、中间 30 场验证、最后 75 场留出。训练集仅搜索固定 gamma 网格 `[0.8,0.9,1.0,1.1,1.2,1.3]`，以多分类 LogLoss 最小选择；验证和留出阶段不再拟合。候选把平局概率乘以 gamma 后整体归一。

训练选择 gamma=0.8。这是该历史样本的结果，不应据此认定所有比赛都该降低或提高平局概率。

|分组|场数|基线 Brier|候选 Brier|基线 LogLoss|候选 LogLoss|
|---|---:|---:|---:|---:|---:|
|训练|119|0.179831|0.179139|0.919188|0.916771|
|验证|30|0.192980|0.191120|0.982834|0.974348|
|留出|75|0.167433|0.165011|0.864906|0.854304|

留出 Brier 差值（候选－基线）-0.002422；按六个比赛日期组进行 2,000 次成对 bootstrap，95% 区间 [-0.005015, -0.000067]。日期组少、来源时间证据不足，仍保持 research-only；未扩大网格、未用留出结果选新参数。

224 场基线方向准确率 59.82%；比分 Top1 28/224、Top3 82/224、Top5 114/224；进球期望平均偏差 -0.0461 球。这些是历史研究描述，不是预测承诺。

## 全流程检查及本轮修复

|环节|发现的问题|本轮处理|
|---|---|---|
|采集时间|Titan 数据集的快照时间在连续请求之前生成|快照改为全部采集完成时；各市场 captured_at 在数据取得后记录，另存采集开始/完成时间|
|输入校验|未来快照、等于开球的快照、带未来日期的战绩可以进入计算|拒绝这些输入；无效赔率、负进球、非整数竞彩让球线及非法时间也明确拒绝|
|预测生成|只有数据快照时间，缺少真实生成完成时刻|增加 started_at/generated_at/decision_at；真实预测完成时已开球则拒绝|
|历史回放|虚拟 asof 与真实生成时刻易混用|明确 historical_replay，禁止写入正式赛前预测表|
|数据库留档|predicted_at 错用了 snapshot_at；保存只用展示概率|改存真实生成时刻与全精度三类概率；核对结果和输入球队/开球身份|
|数据库写入|应用检查后到 SQL 执行之间可能跨过开球|INSERT SELECT 使用数据库 clock_timestamp() 再检查；保留已存记录的幂等 no-op|
|API 保存|保存失败被静默吞掉|返回 saved / failed / unavailable；失败回滚，不能把返回预测当作已封存|
|竞彩玩法|旧批处理把亚盘取整冒充竞彩整数让球线，并用舍入 λ 重算矩阵|只复用引擎基于输入竞彩线的派生概率；没有官方线就缺失，不取整猜测|
|比分展示|Top5 容易被误读为完整覆盖，平局备选不显眼|显示 Top5 总概率与其余比分概率，显示平局排名、次选和最高概率平局比分|
|结算评分|竞彩让球净胜球用了减线而不是加线|按 home_goals + line - away_goals 结算；正负线均有回归测试|
|复盘指标|只看 Top3、绝对进球误差、主胜校准；缺失比分记为未命中|新增 Top1/Top5、平局 Brier、进球有符号偏差、三类分桶校准，分别保留有效分母|
|RPS|观测 CDF 被重复累加，完美预测也不能得到零分|修正观测累计分布，三类完美预测均验证 RPS=0|
|复盘接口|读 backtest_results，但现有结算器写 settlements；无写入链路|改为 predictions JOIN settlements，直接从概率和实际结果计算评分|
|影子融合|同一开球时刻多场只计一个有效样本；缺失信号因少累积损失可能占优|逐比赛计有效样本；仅比较共同覆盖的信号，少于两个共同信号不生成权重|
|批处理可靠性|部分路径硬编码，日键随服务器时区变化，数据库失败污染后续事务|相关入口使用仓库相对路径；竞彩日键用 Asia/Shanghai；失败回滚|

## 验证与迭代结论

竞彩及公共采集/API 测试：351 passed，1 skipped；结果见 validation/jingcai-v211/pytest-results.txt。跳过的是未安装 penaltyblog 的 Pi-rating 影子模块，不是竞彩主引擎。

同样 224 场历史输入在远端基线 v2.10 和本次 v2.11 分别运行，方向变化 0、Top1/Top3 命中变化 0。新旧概率最大差约 0.0000503，来自旧展示概率的四位舍入。没有把这点差异当成精度提升；本次生产迭代主要修正流程、证据和评估。候选校准单独留存，生产参数文件未改。

## 尚不能宣称完成的验证

- 当前没有 DATABASE_URL，数据库 SQL 与 API 保存分支通过 mock 验证；未执行真实 PostgreSQL 端到端部署验收。
- 旧采集/结算代码仍缺少统一 HTTP 原始响应、签名和身份核验链。新时间字段保证流程时间关系，不会自动证明每个来源真实可用；无日期战绩仍无法严格核验。
- 旧日期专用预测脚本未全部迁移至一个生产入口。API 与 batch 的 form-only 校准策略仍存在差异，未来必须统一入口与策略后积累同版本前瞻样本。
- 看板和 API 的聚合是按预测记录统计，交互重复预测及跨版本应单独去重/分组；不能把全部行当作独立比赛数或直接用于选模。
- API 返回 saved 也不是密码学封存；正式前瞻验收仍需生成、持久保存和来源可用时间的独立证据。
- 九月历史研究不能替代更多日期和新比赛的验证。单轮十二场复盘不足以重估全部结构参数。

## 复现

```bash
python scripts/evaluate_jingcai_v211.py
python -m pytest tests collector/tests -q --ignore-glob=tests/test_beidan*
```

主要依赖：pytest、numpy/scipy、fastapi、soccerdata/pandas；API 的 DB 功能还需要 psycopg 与 sql/001、002 结构。这里没有请求远端数据、推送分支、合并 PR 或部署服务。

机器可读结果：research-evaluation.json、baseline-comparison.json、draw-calibration-candidate.json；候选文件 production_enabled=false。
