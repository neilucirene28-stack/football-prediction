## 可执行核验

从 `beidan_independent` 目录运行：

```bash
PYTHONPATH=. python3 -m unittest discover -s tests -q
PYTHONPATH=. python3 -m beidan_bd1.scheduled_collection --config data_sample/scheduled_collection_v29.json --state-dir /var/lib/beidan-collector/v29
```

第二条会核验并写入实际采集记录，勿在别的工作目录运行。修改注册表/配置必须使用新的状态目录。中断后完整采集记录会重新审计；未完成的原件保留，不补造成功记录。

部署模板在 `deploy/`，管理员需按真实检出路径和运行用户调整。模板存在不等于服务器已上线；Muse仅上传代码和PR元数据，不承担部署。

`scripts/audit_official_resources.py` 可离线重放全部新来源与两个解析器，输出文件使用独占创建。核验结果在 `outputs/v29_official_resource_audit.json`，12场提案在 `outputs/v29_12_native_fixture_proposals.json`。原始大文件采用可还原、逐片校验的无损归档。

旧模型账本保持179池、1231历史、95唯一预测、19已结算、76待赛果、84未预测。正式Brier仍0.20622960801176707；新增来源发现不是独立验证样本。按用户要求，本轮不扩展最后一项真实前瞻验证的验收范围。生产资格仍false。
