# 足球采集与预测项目迁移包

本包整理自服务器上当前可读取的源码快照，目标是迁移到另一款 AI 编程/分析软件继续维护。

## 项目组成

- `collector/`：Node.js + Playwright 采集器。按配置访问小店数据页面，保存比赛列表与页面模块响应；Docker Compose 单独运行。
- `prediction/backend/`：FastAPI 后端、PostgreSQL 数据结构、来源适配与规范化、比赛资料 API、采集结果同步脚本、测试。
- `prediction/docker-compose.yml`：后端与数据库部署定义。数据库密码等通过未打包的环境配置提供。
- `prediction/sync_collector_v2.sh`：采集结果同步入口。
- `prediction/RELEASE_NOTES_collector_v2.md`：采集数据接入说明。
- `GPT足球量化模型V4.2.md`：交给新 AI 侧执行的预测规则。
- `新AI导入提示词.md`：迁移后可直接发给新 AI 的启动说明。

## 数据流与职责

1. 服务器采集器从小店网页获取比赛与市场数据，落到服务器数据目录。
2. 同步脚本把规范化数据写入 PostgreSQL。
3. FastAPI 提供已入库的比赛与数据接口。
4. AI 助手读取接口或用户提供的数据后执行分析、概率估计和赛后复盘。

当前后端里的预测相关代码带有数据就绪检查与安全降级，不代表一套已经验证准确率的完整生产预测模型。V4.2 文档是分析规范，模型是否有效需要历史时间序列回测验证。新 AI 不应声称已访问服务器，除非确实配置了授权连接器/API 并成功读取到数据。

## 未包含内容

为防止泄露凭据或隐私，本包不包含：
- `.env`、数据库口令、API key、登录 Cookie、浏览器 profile；
- PostgreSQL 数据库文件、比赛原始采集 JSON、运行日志和备份；
- 服务器上的部署镜像与容器状态；
- 外部托管的 Workbuddy 网站工程源代码（未在已检查的服务器源码目录中找到）。

另附的 `.env.example` 仅用于说明需要哪些配置；须在新环境自行填写并妥善保管密钥。

## 启动前检查

- 先阅读两个项目的 README、Dockerfile、Compose 和同步脚本。
- 配置环境变量与采集站点入口；不要把真实密钥提交到版本库或发给 AI。
- 新环境应先用测试/只读模式验证页面访问和数据映射。
- 数据库需执行 `prediction/backend/sql/` 下按序迁移。
- Python 依赖见 `prediction/backend/requirements.txt`；采集器使用 Node 与 Docker，版本见 `collector/package.json`。
- 做任何预测前，检查比赛时间、赛前数据时间戳、赔率类型和来源；只使用开赛前数据做赛前盲测。

## 来源与快照边界

这是 2026-09-28 从服务器现存源码整理出的迁移副本，不等于完整服务器镜像或经过重新部署验收的 release。源码里可能保留了历史兼容适配器和测试工具。迁移后先做差异审查、依赖审计与部署演练，不要直接覆盖现有生产实例。
